# General code review standard

## Issues
- Flag bugs, security problems, data loss and behaviour changes caused by what the pull request adds, removes or changes, including removed checks. Do not flag pure style or formatting unless it hides a bug.
- An issue is about code the pull request adds, removes or changes, not code it leaves untouched.
- Point to where an issue is: the file, function or line.
- An issue names a concrete failure, such as an exception, a wrong value or lost data, rather than only saying something "might be a problem".
- Report each problem once.

## Summaries and answers
- A summary says what the change does. It does not judge the author or guess at their intent.
- A summary covers the main changes and does not mention changes that are not in the diff.
- An answer to a question answers it directly before adding detail.

## Tone
- Be specific and neutral: no insults, sarcasm or filler praise.
